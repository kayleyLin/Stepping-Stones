铺路石志愿者调配助手

录入志愿者与班级数据，自动排出通勤总时长最短的分配方案。 硬约束是时段完全匹配、每人只带一个班、班级人数不超需求； 优先级是按上传表格里的教学点与班级顺序优先安排，再尽量配满，最后压通勤时间。

1

录入数据

三种录入方式任选：上传原始 Excel（自动识别 vol info / site info 两张表， 合并单元格会向下填充）、从 Excel 复制一片区域直接粘贴到表格里、或者手工逐行填。 时段可以写「周六上午」也可以写「Saturday morning」。地铁站多个用分号隔开； 若还有其他就近地铁站，或最近站点可换乘的其他线路，请写在补充地铁站列。

只填英文的站名、或者写法和官方站名不一致的，在这里建立对应关系。 表里已经预置了三条来自 25 Spring 数据的映射。

2

规则参数

默认值来自需求沟通记录，一般不用改。

3

人工锁定（可选）

已经想好去哪的老志愿者可以先钉死，他们和占用的名额会在计算前扣掉， 模型只排剩下的人。如果锁定的组合本身时段不匹配或通勤超限，会报出来而不是默默接受。

4

通勤时间来源

Key 的类型。在 高德控制台 创建应用后添加 Key，服务平台选 Web端(JS API)，会同时生成一个安全密钥，两个都要填。
高德的 Web服务 类型面向企业/服务端场景，个人开发者账号通常申请不到， 所以这里走的是 Web端(JS API) 这条路：加载高德 JS SDK，用内置的 AMap.Transfer 公交换乘插件查询。
先点「测试 Key」，一次调用就知道能不能用，不用等跑完一整批才发现填错了。
Key 和安全密钥都不会被保存，每次要重新填。录入的数据和通勤缓存会自动存在本机。
调用量。只查时段能匹配上的站对，40 人 30 班约 236 次。 结果自动缓存，项目点站点固定不变，下学期只需为新增的志愿者站点补算。
连续失败会自动停下并说明原因，不会白跑几百次。个别站对查不到时退回本地估算，并在结果里标出来。
字段名尚未用真实数据核实过，浏览器控制台会打印前几条原始返回 （[高德原始返回] 开头），如果换乘次数看起来不对，把控制台内容发给我核对。

数据录入后按钮才会亮。40 人 30 班的规模，本地估算是瞬时的； 走高德约需一分半，中途可以取消，已经调用过的不会浪费。
5

分配方案

求解方法：带凸费用弧的最小费用流，等价于「表格顺序覆盖率 → 安置人数 → 总通勤代价」三层字典序目标， 结果是全局最优且可复现。已与 Python 版 CP-SAT 求解器在同一份数据上比对，三层目标值完全一致。
地铁拓扑数据来自高德地图公开接口快照，含 15、17、18 号线。
录入的数据与通勤缓存自动保存在本机浏览器，刷新不丢；高德 Key 不保存。
单文件离线可用。上传 Excel 需要联网加载解析库；如果离线打开，请用复制粘贴方式录入。
